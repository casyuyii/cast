突然想到一个很感兴趣的问题.

在玩卡牌游戏的时候. 通常卡组都是有一个"卡组代码"的. 这个代码可以帮助你快速组建卡组.

那么. 这东西是怎么实现的? hash? 或许可以. 但是问题是. 每当卡池新增一张卡. 那得滋生 n 倍的 hash code. 这肯定不现实. 这是个只想想. 都觉得头疼的数据量提升. 

(n 等同于卡组最多可组数量. 比如. 卡组最多只能组 20 张卡. 假设初始只有 20 张卡. 那么 hash 表的大小为 1. 此时新增一张卡. 而这一张卡可以替代 20 张中任意一张卡. 那么就会生成原有的 1 + 额外生成的 20 种卡组) = 21 种卡组. 😨)

这个问题的核心不在于效率. 因为卡组是已知的. hash 表可以提前生成. 问题是数据的量. 

(除此之外, 还需考虑的是. 每张卡可能不止带1张)

那么. 他们是如何解决这个问题的呢?

这肯定是一个需要将每个可利用数据都利用到极致的编码.  

emm... 既要保证数据长度. 又要关心效率. 还要注意数据量. 同时, 可以的话, 还不能将编码方式暴露给用户(可能会有潜在的安全问题). = = 不是一个简单问题啊... 

(而这样的问题就在我身边, 而我此时才意识到)

一种比较廉价, 但是相对会有些许限制的方法是. 提供用户一个可编码的工具(通常可以是网页)

hash 表中只记录用户上传的卡组. 同时对 hash 表容量上限做限制(可以采用最少/最早使用卡组记录被覆盖的形式来提高效率) 这种方式显而易见地限制了用户的自由性. 同时可能存在失效卡组码的情况. 但是相对会好做很多. 并不是完美的解决方案. 但却可行.
